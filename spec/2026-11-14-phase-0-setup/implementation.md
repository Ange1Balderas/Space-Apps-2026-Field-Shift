## UI review

CLAUDE.md asks for the `ui-reviewer` subagent after a UI change. That subagent was not registered in the session that built this phase, so a general-purpose agent was given `.claude/agents/ui-reviewer.md` as its checklist. It ran after the first app commit ("Phase 0: scaffold Next.js app, ..."). A usage limit stopped it before its own final check, so its report is a draft. Findings 1 to 5 were confirmed in the browser or in MapLibre's stylesheet before anything was changed.

| # | Finding | Level | What was done |
| --- | --- | --- | --- |
| 1 | The map's loading placeholder used `bg-accent`, which on this palette is almost the page colour, so loading looked like a blank panel | Must fix | Fixed: `bg-muted` in `components/ui/skeleton.tsx` |
| 2 | The loading and error overlays had no z-index, so MapLibre's controls (z-index 2) showed through the error notice, and the covered map could still take keyboard focus | Should fix | Fixed: `z-10` on both overlays; the map is `inert` while the error notice is shown |
| 3 | The map canvas is a tab stop with no visible focus, because MapLibre clips the default outline | Should fix | Fixed: an inset focus outline in the ring colour |
| 4 | "Loading the map" was in the first render, so screen readers never announced it, and the end of loading was silent | Should fix | Fixed: one status region that is always on the page and changes its text |
| 5 | One failed tile before the first load could raise the full error notice, and the copy blamed the map service whatever the cause | Should fix | Fixed: tile errors are ignored; the copy now says "Check your connection, then try again." |
| 6 | The header line and the page description say what the tool does, which the page cannot do yet | Should fix | Not changed. SPEC user flow step 1 asks for one line on what the tool does, and the "Early preview" badge and the empty panel say what is missing. Angel's call |
| 7 | The disclaimer banner sits outside every landmark | Polish | Not changed |
| 8 | On a tall, narrow viewport a strip of background could show under the map | Polish | Not changed. Not seen at 390 x 844 |
| 9 | A stalled style request would leave the placeholder up with no message | Polish | Not changed. A timeout belongs with the Phase 1 data loading |

The draft also listed what it checked and found fine: colour tokens, computed contrast, landmarks, layout, reduced motion, the disclaimer, no images, `"use client"` coverage and the compiled classes.

Two more problems turned up after the review, while taking screenshots, and were fixed in `components/MapView.tsx`:

- The loading placeholder pulses between solid and half transparent, so the half-drawn map controls showed through it. It now sits on a solid backing.
- Kansas was fitted once, using the size the map had when it was created. If the panel was resized afterwards, or was created before it had a size, Kansas no longer filled the view. The map now fits Kansas again whenever its panel changes size, until a person pans or zooms.

## Deviations for Angel to review

1. **Fonts.** SPEC says to copy the `:root` and `.dark` blocks as-is and to use Geist. Stragents `styles.css` loads Geist but sets `--font-sans` to "Inter" and `--font-mono` to "JetBrains Mono", neither of which it loads, so a literal copy renders a fallback font. Here the font tokens point at "Geist Sans" and "Geist Mono", and the unused serif token is dropped. All colour, shadow, radius and spacing tokens are unchanged.
2. **`CropId`.** The SPEC contracts use `CropId` but never define it. `lib/types.ts` defines it as `"winter_wheat" | "corn" | "grain_sorghum" | "soybean" | "alfalfa" | "cover_crop"`, taken from the crops named in the SPEC rotation library. This is the only thing in the file that is not in the SPEC. Please confirm or change it before Phase 3.
3. **Extra ported files.** `components/notice.tsx` is not on the SPEC list but `states.tsx` imports it. `components/ui/badge.tsx` and `components/ui/sonner.tsx` were added because the UI rules name badges and `lib/feedback.ts` needs the toast host. `lib/utils.ts` holds `cn()`.
4. **`cn` import and `"use client"`.** Stragents UI files import `cn` from the npm package `cn`; here they all import it from `@/lib/utils`, as SPEC says ("fix the import alias"). Stragents is a client-rendered app, so seven files needed a `"use client"` directive to work as Next.js client components.
5. **`maplibre-gl` is pinned to `^5.24.1`, not the latest 6.x.** With 6.18.0 the production build served a 404 page for the map's web worker file ("Worker failed to load"), so no map drew. Version 6 ships the worker as a separate file that this bundler setup does not pick up without extra wiring. Version 5 bundles the worker and works with no configuration.
6. **`@types/node` is `^22`, not the template's `^20`.** Vitest 5 requires 22 or newer as a peer, and the project baseline is Node 22.
7. **Dropped from `styles.css`:** the `@tailwindcss/typography` plugin (not installed, not used) and the `#app` selector (Next.js has no `#app` element).
8. **`AGENTS.md`.** `create-next-app` generates it, and `next dev` re-creates it whenever a coding agent runs the dev server. It only tells agents to read the Next.js docs bundled in `node_modules`. It is committed so the tree stays clean. To remove it for good, set `agentRules: false` in `next.config.ts`.
9. **Template defaults kept:** `cacheComponents: true` and `partialPrefetching: true` in `next.config.ts`, and Tailwind through the `@tailwindcss/turbopack` loader. These are what `create-next-app` 16.4.6 generates.
10. **`dev:mock`.** The script exists because CLAUDE.md requires the name. It sets `NEXT_PUBLIC_DATA_MODE=mock` and starts the dev server. Nothing reads the flag yet: mock data is Phase 1 work.
11. **Phone layout.** SPEC wants the panel as a bottom sheet on phones. The placeholder panel simply stacks under the map; the ported `sheet` component is ready for the real panel.
12. **Sticky two-column grid.** `agent-detail.tsx` was used as a pattern only, as the SPEC table describes. No file was copied from it.
13. **Skeleton colour.** The ported `skeleton.tsx` used `bg-accent`. On this palette the accent token is almost the same colour as the page background, so every loading placeholder was invisible. It now uses `bg-muted`. This is the only ported component whose styling differs from Stragents.
